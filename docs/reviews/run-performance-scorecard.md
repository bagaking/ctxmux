# Run 性能记录：收益、代价与未验收指标

本记录汇总已经执行的观察，以及有明确假设的数学推导。
[性能标准](../benchmark-standard.md)和[存储 benchmark 合同](../replay-storage-benchmark.md)
继续拥有验收要求；本记录不增加 SLA、容量限制或新的通过门槛。
性能包含正确性、可靠性、吞吐、延迟、公平性、资源、容量、恢复和可用体验。

## 已交付：事务统一同步 replay 文件

对照源码为 `6e27fdc`，候选为 `8eab24f`；生产改动提交为 `019f496`。
同一事务写完所有 Run 的 payload 后同步一次，然后提交 SQLite FULL 索引。
原始字节、既有收集窗口、资源政策和持久性要求保持。
完整方法、源绑定、失败保留及故障证明见[验收报告](transaction-replay-sync-qualification.md)。

以下为 macOS arm64、32 个真实私有 Run、三轮交错对照。
短消息先取每轮八次释放的中位数，再取三轮中位数；大块输出取三轮中位数。
实时交付和持久化均测量整批完成，不是首字节延迟或直接 syscall 耗时。

两个真实 Run 和两个公共 Client 验证二进制输入输出、精确 receipt、Ctrl+C、
断开重连及冷历史恢复；另有真实 CLI 的两轮 attach/input/interrupt/detach。
所有私有 Run 正常收尾，不接触用户 Runtime。压缩、物理断电、原 Linux 持续负载
及 AgentMux GUI 不属于此局部验收。

独立新建的 8192 Run 短负载不能替换这些失败。读取补测核对 180 组、2460 条流，

均保留各自验收。观察器成本、实时回退和数据库压力不能被落盘延迟收益盖掉。

## 压缩几何小实验

[现场 grounding](replay-storage-usage-grounding.md)记录了同一份 7154811 B、
23945 个小片段的样本。以下是 zlib 单轮内存探索：速度为原始字节量除以 CPU 时间，
尚无生产磁盘读取、并发或恢复结论。所有方式解码后均等于原始选定字节。

| 几何                         | raw/encoded | payload 空间减少 | 压缩 MiB/CPU-s | 解码 MiB/CPU-s |
| ---------------------------- | ----------: | ---------------: | -------------: | -------------: |
| 每个记录片段独立压缩         |       2.62× |           61.77% |           32.3 |            406 |
| 独立 64 KiB 帧               |      11.48× |           91.29% |          134.3 |           1582 |
| 独立 256 KiB 帧              |      13.05× |           92.34% |          133.2 |           2419 |
| 独立 1 MiB 帧                |      13.50× |           92.59% |          133.2 |           2188 |
| 保留上下文、每个小片段 flush |       9.96× |           89.96% |           72.6 |           1798 |

256 KiB 增至 1 MiB 仅再减少约 3.35% 的编码体积；容量收益与短读成本需要一起比较。
私有聚合原件在 `.bagakit/storage-grounding/geometry-pilot-2.private.json`。
片段不是生产到达时间，样本不是自然总体，也没有独立 held-out codec 对照。

## 可计算的理论值

这些是指定条件下的公式或算例，不是未执行 benchmark 的预测成绩。

| 指标               | 公式或条件算例                                                                                     | 限制                                                                             |
| ------------------ | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| payload 同步调用数 | 同一事务 R 次 → 1 次，减少 1−1/R                                                                   | R 为原非空写入行数                                                               |
| 同步后的总耗时倍数 | (A+R×s)/(A+s)                                                                                      | A 是其他成本，s 是一次同步成本；32 次时上限 32 倍，不能外推总体容量              |
| writer 打开次数    | 事务内 K 个 Run 的 K 次 → 1 次                                                                     | 仅 writer 路径；不表示常驻 FD 数同样下降                                         |
| 压缩 payload 空间  | P/c                                                                                                | c 为压缩比；10 倍时减少 90%，索引和垃圾另计                                      |
| 整体空间收益       | (P+M)/(P/c+M)                                                                                      | M 为其他占用；不能直接套用 payload 压缩比                                        |
| 空间算例           | 约 156 MiB payload＋90.75 MiB 索引，payload 压缩 10 倍时这两部分节省约 56.9%，同资金容量约 2.32 倍 | 未计 WAL、垃圾、checkpoint 和压缩索引                                            |
| 顺序读倍数         | 1/(1/c+B/D)                                                                                        | 串行读盘与解码；c=10、B=500、D=2500 MiB/s 时约 3.33 倍；缓存命中时可能没有该收益 |
| 单块短读放大       | 整块解码时 F/q                                                                                     | 一个 256 KiB 块中读 4 KiB 可解码 64 倍数据；跨块额外计                           |
| 共享重复解码       | K 次 → 1 次                                                                                        | 相同块且有共享实现；32 个 Client 的该部分计算可减少 96.88%，传输和缓存成本另计   |
| 索引几何           | 1 GiB/256 B 约 419 万条；1 GiB/256 KiB 为 4096 条                                                  | 仅理想单帧单索引记录的算例，不是现有索引实现或文件缩小倍数                       |
| 垃圾回收几何       | 旧快照 generation 与有效 payload 差约 313.3 MiB                                                    | 须验证全部引用；不是当前可直接删除的空间                                         |
| 历史长度           | 物理资金与逻辑保留政策共同决定                                                                     | 固定原始字节保留上限未变时，压缩本身的长度收益为零                               |
